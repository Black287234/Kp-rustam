## Что потребуется
- .NET SDK 10 (проверка: `dotnet --version`, версия должна начинаться с `10.`);
- любой браузер.

## Как запустить
```
dotnet run --project src/TransportOrders.Web
```
После сообщения `Now listening on: http://localhost:5113` открыть в браузере http://localhost:5113.
Остановка — `Ctrl+C`. В Visual Studio 2026 открыть `TransportOrders.slnx` и нажать F5.

## Статусы заявки
```
новая ──назначить автомобиль──► автомобиль назначен ──отметить выезд──► в пути ──завершить──► выполнена
  │   ◄────снять автомобиль────────┘          │
  ├──отклонить (с причиной)──► отклонена       └──отменить (с причиной)──► отменена
  └──отменить (с причиной)───► отменена
```
Правила назначения: автомобиль исправен («в строю»), мест не меньше, чем пассажиров, нет пересечения по времени
с другими заявками этого автомобиля в статусах «автомобиль назначен» и «в пути». Поездки «встык» (одна до 11:00,
другая с 11:00) не пересекаются. Выезд отмечается не раньше чем за час до начала. Нельзя отправить в ремонт
или списать автомобиль, за которым закреплены предстоящие поездки.

## Сценарии демонстрации
1. **Успешное назначение.** Заявка ЗТ-0006 (суд, завтра 10:30–12:30, 2 пассажира) → «Назначить» с автомобилем
   В530ОР 186 → статус «автомобиль назначен», в журнале запись, на `/Board` появилась полоса.
2. **Отказ.** Та же заявка ЗТ-0006 и автомобиль А214КМ 186: он занят заявкой ЗТ-0005 с 10:00 до 11:00,
   поэтому в списке недоступен. При попытке отправить запрос в обход списка — сообщение «Автомобиль А214КМ 186
   занят в это время: заявка ЗТ-0005…». Второй отказ: для делегации из 12 человек (ЗТ-0007) легковые
   автомобили недоступны: «мест 4, а пассажиров 12».

## База данных
- SQLite, доступ через Dapper (пакеты `Dapper` и `Microsoft.Data.Sqlite` указаны в `TransportOrders.Web.csproj`).
- Файл базы: `src/TransportOrders.Web/App_Data/transport.db`, создаётся при первом запуске.
- Структура и учебные данные задаются SQL-скриптами в `src/TransportOrders.Web/Data/Migrations`:
  `0001_schema.sql` — таблицы `car`, `employee`, `trip_request`, `trip_log`; `0002_sample_data.sql` — 8 автомобилей,
  10 сотрудников и 10 заявок с датами вокруг дня первого запуска; `0003_dispatch.sql` — причина закрытия заявки,
  индекс и триггер, который не даёт базе сохранить двойное назначение автомобиля.
- Выполненные скрипты записываются в таблицу `schema_history`, повторно они не запускаются.
- **Вернуть учебные данные:** остановить приложение, удалить папку `App_Data` и запустить снова.

## JSON API
- `GET /api/cars`, `GET /api/cars/{id}` — автомобили;
- `GET /api/trips?Status=New&OpenOnly=true` — заявки с отбором; `GET /api/trips/{id}` — одна заявка;
- `GET /api/cars/{id}/busy?from=2026-11-20T09:00&to=2026-11-20T12:00` — занят ли автомобиль и чем.

## Связи таблиц
- `trip_request.requester_id` → `employee.id` (кто подал заявку);
- `trip_request.car_id` → `car.id` (назначенный автомобиль, может отсутствовать);
- `trip_log.request_id` → `trip_request.id` (журнал заявки).
