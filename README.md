## Что потребуется
- .NET SDK 10 (проверка: `dotnet --version`, версия должна начинаться с `10.`);
- любой браузер.

## Как запустить
```
dotnet run --project src/TransportOrders.Web
```
После сообщения `Now listening on: http://localhost:5113` открыть в браузере http://localhost:5113.
Остановка — `Ctrl+C`. В Visual Studio 2026 открыть `TransportOrders.slnx` и нажать F5.

## Что уже работает
- **Автомобили** (`/Cars`): список с поиском по госномеру, марке и модели и отбором по состоянию, карточка, добавление, изменение.
  Автомобиль не удаляется: выведенный из автопарка получает состояние «списан».
- **Сотрудники** (`/Employees`): список с поиском, карточка, добавление, изменение. При увольнении снимается отметка «Работает».
- **Заявки** (`/Trips`): список, карточка с журналом, подача новой заявки, изменение заявки, пока она в статусе «новая».

Проверки при вводе: формат госномера (А123ВС 186), уникальность госномера и табельного номера,
время возвращения позже выезда, поездка не дольше 12 часов и не в прошлом, уволенный сотрудник не подаёт заявки.

## База данных
- SQLite, доступ через Dapper (пакеты `Dapper` и `Microsoft.Data.Sqlite` указаны в `TransportOrders.Web.csproj`).
- Файл базы: `src/TransportOrders.Web/App_Data/transport.db`, создаётся при первом запуске.
- Структура и учебные данные задаются SQL-скриптами в `src/TransportOrders.Web/Data/Migrations`:
  `0001_schema.sql` — таблицы `car`, `employee`, `trip_request`, `trip_log`; `0002_sample_data.sql` — 8 автомобилей,
  10 сотрудников и 10 заявок с датами вокруг дня первого запуска.
- Выполненные скрипты записываются в таблицу `schema_history`, повторно они не запускаются.
- **Вернуть учебные данные:** остановить приложение, удалить папку `App_Data` и запустить снова.

## Связи таблиц
- `trip_request.requester_id` → `employee.id` (кто подал заявку);
- `trip_request.car_id` → `car.id` (назначенный автомобиль, может отсутствовать);
- `trip_log.request_id` → `trip_request.id` (журнал заявки).
